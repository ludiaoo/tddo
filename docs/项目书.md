# TDDO 项目书 · 卡车-无人机联合配送优化器

> 一句话：**把"卡车带无人机送货"写成一个可解的优化问题**——决策车怎么走、机从哪起飞、
> 在哪会合、带几块电池；用混合整数规划建模，用自适应大邻域搜索解到实际规模，
> 再用精确解给结论定级；最后回答的不是"能省多少"，而是"这个数在什么条件下成立"。

---

## 2. 问题定义

### 2.1 场景

一辆卡车带若干架无人机沿路网送货。卡车在客户点停靠时可放无人机出去，无人机服务
1..k 个客户后在**后面某个停靠点**落回车上；期间卡车继续开。客户有派件与取件需求、
有时间窗；城市上空有若干**时空禁飞区**（空间是固定的圆，时间是一个时段）。

### 2.2 归类

它属于 **VRP 家族里的"多层级 + 同步"分支**：

```
VRP
├── 2E-VRP（两层：卫星站转运）
├── VRP with trailers / synchronized routes（车辆必须同时到达某点）
└── truck-drone tandem（本项目）
      ├── 无人机在卡车停靠点起降（parcel lockers on wheels）
      ├── 一次架次服务 1..k 个客户（mFSTSP 形态）
      ├── 双向载荷（派件 + 取件）
      ├── 时空禁飞区（航段可绕、节点可禁）
      └── 本项目扩展：一车多机、同节点换电、跨段锚点、电池库存、换电耗时
```

### 2.3 三处让它变难的耦合

1. **时间同步**：无人机起飞时刻由卡车到达起飞点决定，落地时刻由飞行与客户服务决定，
   卡车在回收点必须等（或无人机悬停等车）——两边互为约束，不能先路由后调度地拆开做；
2. **能量-载荷耦合**：单段能耗 = 距离 ×（单位载荷能耗 × 机上载荷 + 空载系数），
   载荷又随每个客户逐点变化，所以能耗必须逐段推进，不能整段平均；
3. **时空禁飞区**：同一段航程在禁飞时段内不可飞、时段外可飞，绕行距离是**时间相关**的
   分段函数——这是模型里最贵的非线性来源（切线几何 + 大 M）。

## 3. 建模

### 3.1 决策变量（按语义分五组）

| 组 | 变量 | 含义 |
|---|---|---|
| 路由 | `x[k,i,j]` | 卡车 k 走弧 (i,j) |
| 架次 | `y[k,i,j]` | 无人机从 i 起飞、在 j 回收（i,j 是卡车路径上的两个停靠点） |
| 起降标志 | `wl[k,i]` / `wr[k,i]` | 在 i 起飞 / 在 i 回收 |
| 时间 | `Tt[k,i]`（卡车到）/ `Td[k,i]`（无人机起飞） | 同步的核心 |
| 载荷与能量 | `F/G[k,i]`、`ft[k,i]`、`E[k,i]`、`ec[i,j]` | 双向载荷、起飞装载、累计能耗、单段能耗 |

### 3.2 约束族（七组，共 79 条）

| 组 | 作用 | 实现要点 |
|---|---|---|
| 路由与流 | 每个客户恰好被访问一次、卡车出入平衡 | 结构自动成立（解的表示把"谁服务谁"写死） |
| 架次耦合 | 起降点必须在卡车路径上、起降成对 | `wl ≤ Σx`、`wl+wr ≤ 1+Σx`（拆三条，防"凭空起飞"） |
| 时间同步 | 卡车等机 / 机等卡车 / 服务时长 | `Tt[j] ≥ Tt[i] + sv + launch·wl + τ + recovery·wr` |
| 时间窗 | 卡车与无人机分别判 | 卡车用"不等候到达"比窗口，防靠故意晚出发蒙过去 |
| 载荷 | 卡车容量、无人机容量、回收时清零 | 逐点递推，`fa_in ≤ M(1-wr)` |
| 能量 | 逐段累加、单架次 ≤ η·E_max | 载荷逐段变化，不能整段平均 |
| 空域 | 节点在禁飞期内不可起降、航段不可穿圆 | 切线几何算绕行距离，时间相关 → 需 McCormick 线性化 |

### 3.3 一个关键设计：把一半约束交给"解的表示"

`Solution` 是 `Route` 的集合，`Route` 带一条卡车路径与若干 `Sortie`（起飞位置、回收位置、
服务客户）。于是「无人机只在卡车停靠点起降」「每个客户只被访问一次」「流守恒」
**在数据结构层面就无法被违反**，评估器只检查剩下真要检查的：时间、载荷、能量、空域。

代价是位置下标会随增删平移，所以算子内部一律先转成"按节点编号的锚点描述"再操作
（这一步踩过两次坑，现在有测试守着）。收益是单个候选解评估 ~30 µs——这是 2 000 轮 × 160 次
求解能在 20 分钟内跑完的前提。

### 3.4 模型规模与可解性

| 规模 | 手段 | 结果 |
|---|---|---|
| 10 客户 | Gurobi（`milp.py`） | 4/4 证到 gap 0%，单例 13–254 s |
| 25–100 客户 | ALNS | 与 MILP 的距离 0–1.22% |
| 换电扩展 | Gurobi（`milp_hs.py`，变量按到达/出发拆分） | 4/4 证到 gap 0% |

## 4. 求解

不是为了"两个都做"，而是**各有各的职责**：

| 角色 | 谁来做 | 为什么 |
|---|---|---|
| 给启发式定标 | MILP | 10 客户上算 gap，证明 ALNS 不是在瞎走 |
| 给结论定级 | MILP | "换电更好"升级成"最优值被改写" |
| 实际规模求解 | ALNS | 50/100 客户 MILP 不可解 |
| 交叉校验 | 评估器 | 两套实现互查（MILP 目标值 vs 评估器成本，逐位对） |

### 4.1 ALNS 的五个部件

| 部件 | 选择 | 理由 |
|---|---|---|
| 破坏 | random / worst / related / shuffle | 覆盖"随机扰动 / 拔贵的 / 拔相近的 / 结构重组" |
| 修复 | random / truck / drone / equal | `equal` 是主力（把客户在卡车与无人机间搬），份额约占一半 |
| 接受 | 模拟退火，T0 按算例标定 | 固定初温会让小算例过热、大算例过冷 |
| 权重 | 四档加分 + 0.05 下限 | 下限防"一次走运就锁死" |
| 评估 | `evaluate` 一次给成本 + 违约清单 | 违约码分类（时间窗/容量/能量/空域/并行/电池）便于诊断 |

### 4.2 工程加速（4.6×）

| 手段 | 收益 |
|---|---|
| 几何缓存（禁飞区预筛到节点级） | 最大一项：原实现每次 O(\|H\|) |
| 单路线评估记忆化（按签名） | 修复算子反复评同几条路线 |
| `fast=True` 违约早退 | 明显不可行的候选从 O(路径长) 降到 O(违约位置) |
| 多进程 + 逐行落盘可续跑 | 160 次求解在 10 进程下约 20 min，且中断可续 |

## 5. 验证：四道闸门

这是我认为最值得讲的部分——**不是跑完就报**。

| 闸门 | 做法 | 拦住什么 |
|---|---|---|
| ① 逐位回归 | `golden_check`：5 个固定配置，任何默认路径改动必须结果不变 | 性能优化偷偷改变解 |
| ② 配对统计 | 同种子配对，而非"各种子取最优" | 极值偏差（踩过 4 次，最大虚高 17%） |
| ③ 最优性闸门 | 新模型加回限制必须与原形式逐位相同；放开必须严格更优且 gap 0 | 模型写错/写松 |
| ④ 双实现互查 | MILP 的解转成 `Solution` 用评估器复算成本与可行性 | "模型自己算得很开心" |

敏感性分三层做：**单参数**（14 组扫描）→ **分布**（生成参数四组扰动、空间聚簇）→ **口径**
（悬停计价、换电耗时、电池库存）。第四层"联合敏感性"明确标为未做。

## 6. 三条洞察

### 6.1 一个变量定义值 1.5%–3.4%

标准建模里常把"在 i 降落"和"从 i 起飞"写进同一个 0-1 变量，于是同一节点只能二选一。
这只是建模便利，物理上没有理由（换电池是常规作业）。把该变量拆成到达/出发两套后：

- 统计：16×10 全量 −2.26%，6×5 子集 −3.37%；
- **最优性**：4 个 10 客户算例的最优值全部下降（−4.33/−0.56/−0.18/−0.17%），
  且解**只违反那一条限制**——说明差距精确地来自这个变量；
- 边界：换电要 2–5 min 时降到 1.6%–2.3%；每车少于 2 块备用电池时降到 1% 以下；一块不带则完全失效。

**洞察**：这类改进的价值不来自算法，来自**把两件事从一个变量里解耦**。

### 6.2 一车两机的边际只值 0.68%

多机（m=2）比单机降 2.94%，但其中 2.26 个百分点与换电重叠；扣掉之后**第二架机的净贡献只有 0.68%**，
拐点在 m=2（m=3 反而 +0.21%）。等资本口径下，多买一辆车（+1 名司机）反而 **+0.67%**。

**洞察**：并行能力的天花板不在"机够不够"，而在"卡车停靠点够不够密"。
它对车队的含义很直接：先加密停靠点，再考虑加机。

### 6.3 学习型方法在这个问题上不划算

12 组负结果：预筛（快 2.1× 但质量掉）、UCB（+3.97%）、DQN（+3.78%）、LLM 造算子（6/7 输给随机）、
周期干预（−1.74%）、锚点平移（+0.62%）。共同机制：**收益来自算子配比，不来自决策智能**，
任何"更聪明的选择"都在破坏那个恰好不错的配比。

**洞察**：在"评估器便宜（30 µs）+ 可行率低"的场景里，先把评估器做快，比把选择做聪明更值。

## 8. 边界与局限

1. **算例自建**：底图坐标来自公开路网数据，需求/时间窗/禁飞区/车队规模按固定规则生成
   （种子固定），所以结论可比、绝对金额不可比。
2. **MILP 不含禁飞区与悬停**：前者是时间相关分段距离、线性化代价过高；后者的最优性结论
   在"悬停免费"口径内成立。
3. **规模上限 100 客户**：无 200+ 外推。
4. **敏感性是单参数的**：四把刀各自测过，**没有做联合**，叠加数值不能外推。
