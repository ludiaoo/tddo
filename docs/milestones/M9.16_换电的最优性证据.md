# M9.16 · 换电放松的最优性证据：4/4 个小算例的「已证明最优」都能被打破

> **结论先行**
>
> | Set | 论文模型 MILP 最优 | 我们的 m=1 | 换电解 | 换机 vs 最优 | 在原模型里唯一违反的约束 |
> |---|---|---|---|---|---|
> | 1 | 98.7240（gap 0） | 99.9330 | **94.4471** | **−4.33%** | `lr_once_0_5` |
> | 2 | 115.9189（gap 0） | 115.9189 | **115.2679** | **−0.56%** | `lr_once_0_8` |
> | 3 | 67.7647（gap 0） | 67.7647 | **67.6454** | **−0.18%** | `lr_once_0_3` |
> | 4 | 73.3771（gap 0） | 73.3771 | **73.2560** | **−0.17%** | `lr_once_0_9` |
>
> **四个算例全部：换电解在论文模型的每一条约束下都可行，唯一违反的就是
> `wl[k,i] + wr[k,i] ≤ 1` 这一条，且每个算例只在一个节点上违反。**
>
> 这比"我们的启发式找到了更好的解"强一个量级——它说明**论文的可行域里少了一个点，
> 而那个点比它自己证明的最优解还便宜**。MILP 的 gap 是 0，所以"最优"是可信的；
> 换电解的可行性由独立评估器 + 逐条约束校验共同确认。

## 1. 证明的逻辑（为什么这个论证站得住）

```
Z  = 论文模型的最优值（Gurobi，gap 0）
X  = 我们的换电解
① X 在论文模型的全部约束下可行，除了 lr_once
② X 的成本 < Z
⇒ 论文模型的可行域遗漏了一个比自身最优解更好的点
⇒ 原模型的最优值被「单个二元变量 w_i」这个建模选择抬高了
```

关键在第 ①：**不是**"我们的评估器认为可行"，而是把 X 的每条卡车弧、每条无人机弧、
每个起降标志都**固定进 Gurobi 的论文模型**，让它判可行性。不可行时它会给出 IIS
（不可约冲突集），我们读 IIS 看冲突落在哪条约束上。

需要强调的是：这个检验同时校验了时间递推、载荷递推、能耗递推、时间窗、容量
——**全部通过**，只有 `lr_once` 一条不通。所以 X 不是"评估器放水"的产物。

## 2. 四个算例的具体读数

`python -m scripts.milp_hotswap`（MILP 臂）+ `solve_milp(..., fix=X)`（钉解检验）。
口径与 `scripts/run_milp.py` 完全一致：**关闭禁飞区**（MILP 不建模 NFZ）。

|---|---|---|---|---|---|---|---|---|
| 1 | 10 | 3 | 98.7240 | 0% | 99.9330 | 94.4471 | −4.33% | `lr_once_0_5` |
| 2 | 10 | 2 | 115.9189 | 0% | 115.9189 | 115.2679 | −0.56% | `lr_once_0_8` |

## 3. 为什么「朴素放松」的 MILP 反而不行

我先试了另一条路：直接在 MILP 里去掉 `wl+wr ≤ 1`，重新求解，希望最优值自己掉下来。
**结果目标值一动不动**（98.7240 / 115.9189 / 67.7647 / 73.3771，与放松前逐位相同），
而把换电解钉进去却报 23 条冲突。查下来是三处耦合：

| 位置 | 原写法 | 为什么在换机点上失效 |
|---|---|---|
| `lr_once` | `wl + wr ≤ 1` | 直接禁止同一节点做两件事 |
| `lr_truck_visit` | `wl + wr ≤ Σx` | 同一个节点被算两次"到访"，右端只有 1 |
| `Td_zero_at_launch` | `Td ≤ M(1-wl)` | 强制 `Td=0`，把"落地时刻"抹掉，`Tt` 就等不到机 |
| `fa / ga / ft` 递推 | 用 `wl[i]` 区分"新架次"与"续飞" | 一个节点既是回收又是起飞时，`fa[i]=0`（刚落地）与 `ft[i]`（新装载）语义打架 |

也就是说：**"一个节点只承担一件事"这个假设不只写在 `lr_once` 里，它贯穿了时间清零、
卡车到访、以及无人机载荷递推。** 去掉一条约束不构成有效的放松，这就是 MILP 目标值不变的
原因——不是换机无效，是放松没放松到位。

要写出**正确的**换电 MILP，需要把无人机载荷拆成「到达量 `fa^in`」与「离开量 `fa^out`」
两组变量（换机点上前者为 0、后者为新装载），时间同样拆成「落地 `Td^arr`」与
「再起飞 `Td^dep`」。这是一次真正的重构，不是改一行。

> 顺带一句：这也解释了为什么原论文不可能"顺手"支持换机——它的 `w_i` 是一个共享的 0-1 变量，
> 一旦拆开，载荷与时间的递推全都要跟着拆。

## 5. 踩坑记录（值得单独记住）

**`disable_nfz(inst)` 返回新对象，不原地修改**（`dataclasses.replace`）。
临时脚本里写成 `disable_nfz(inst)` 而不接返回值，等于什么都没做——禁飞区一直开着，
于是 Set2/3 的"ALNS 无禁飞区"结果实际上是"有禁飞区"，看起来像"ALNS 不稳"。
`scripts/run_milp.py` 里是正确的写法（`inst = disable_nfz(build_instance(...))`），
所以已入库的 `milp_check.csv` 不受影响。

教训：**诊断脚本也要过一遍和主代码同样的口径检查**。这次是靠"Set2 的 ALNS 值恰好等于
bench_main 的值"这个巧合才发现的。

## 6. 复现

```bash
# ① 论文模型的 MILP 最优（已有）
python -m scripts.run_milp --tl 300

# ② 换电放松的 MILP（朴素放松，目标值不变——用来展示放松不完整）
python -m scripts.milp_hotswap --tl 300

# ③ 钉解检验（核心证据）：把换电解固定进论文模型，读 IIS
python - <<'PY'
import copy
from src.alns import solve, disable_nfz
from src.io import load_config, load_sets
from src.generator import build_instance
from src.milp import solve_milp
by = {s["id"]: s for s in load_sets()}
for sid in (1, 2, 3, 4):
    cfg = copy.deepcopy(load_config()); cfg["fleet"]["allow_hotswap"] = True
    inst = disable_nfz(build_instance(by[sid], cfg))          # 注意接返回值
    best = min((solve(inst, seed=s, iters=1500) for s in range(4)),
               key=lambda r: float(r.best_cost))
    print(sid, round(float(best.best_cost), 4),
          solve_milp(inst, time_limit=20, allow_hotswap=False, fix=best.best).status)
PY
```

产物：`results/milp_hotswap.csv`（朴素放松的对照）、终端输出（钉解与 IIS）。
