# 求职评估：这个项目能不能当 VRP 实习的敲门砖

> 评估对象：当前仓库（`src/` 30 模块 6 409 行、`scripts/` 44 个 7 515 行、`tests/` 31 个 2 891 行 / 341 项、
> 110 份结果 CSV、42 份文档、`tddo` CLI + Docker + CI + 一键复现 + 逐位回归）。
> 参照岗位：运筹优化 / 决策优化 / 供应链算法实习生（国内大厂与物流公司为主）。

## 0. 一句话结论

**建模与实验纪律这一层已经超过多数硕士简历，可以直接投"算法研究型"实习；
P0（外部基线与业务换算）、P1（CLI 与容器）、P2（规模压测与文献定位）均已补齐；剩余缺口是真实业务数据与 1000+ 规模。**

| 岗位类型 | 现在能投吗 | 说明 |
|---|---|---|
| 运筹/决策算法研究实习（物流、供应链、配送） | **可以**，材料已够 | 强项正好是这类岗位的核心：建模、精确解定标、统计验证 |
| 算法工程 / 运筹开发实习 | **可以**，材料已够 | OR-Tools 基线与 `tddo` CLI / Docker 交付壳都已补齐 |

## 3. 简历与面试中的可讲性

### 3.1 三条故事线（按"能讲多深"排序）

1. **一个 0-1 变量值 2–3%**（最硬）
   从"同一节点不能既降落又起飞"这个语义冲突出发 → 拆变量 → 4/4 个算例用 Gurobi 证到 gap 0 →
   差距只落在被移除的那条约束上。**这条能证明你会读模型、会证伪，而不是只会调参。**
2. **同一个数在四种设定下从 −3.4% 变到 −1.5%**（最有辨识度）
   悬停是否计电、换电多久、几块电池、算例形态。绝大多数简历只报一个点估计，你报的是区间 + 失效条件。
3. **换到真实路网后，一个结论塌了**（最像"做研究"）
   换电 −2.13% 稳住了，跨段锚点从 −2.40% 归零。**主动报告"我的另一个想法没成立"，可信度比多报一个正结果高。**

### 3.2 简历可用的四条 bullet（已验证数字）

- 独立实现卡车—无人机联合配送求解器（Python，6 千行 / 30 模块，341 项测试，CI 全绿），
  100 客户 2 000 轮迭代约 170 s，单候选评估 30 µs。
- 定位一处建模缺陷（单个 0-1 变量同时表示降落与起飞），用 Gurobi 在 **4/4** 个算例上
  打破原最优值（−0.17% ~ −4.33%），新模型全部证到 gap 0%。
- 完成 11 组单参数敏感性（换电耗时/电池库存/悬停能耗/算例形态/空间分布），
  把"降本 3.4%"收敛为 **1.5%–3.4% 的区间 + 失效条件**，每项 30–160 个配对样本 + 符号检验。
- 将算例迁移到真实城市路网（OSM 单行线 + 高德交叉校验 1 100 个 OD），
  换电收益 −2.13%（35/5，p=1.4e-06）与合成算例一致；同批实验发现另一结论（跨段锚点）在真实路网上归零。

### 3.3 面试会被追问什么（新增三条）

| 追问 | 答法要点 |
|---|---|
| "你的 ALNS 比 OR-Tools/PyVRP 快吗？" | 已跑 OR-Tools：卡车侧 10/25/50 客户差异 ≤0.01%，天河 100 客户 ALNS 纯卡车便宜 4.5% 且墙钟更短；但强调是松弛子问题、限时搜索，见 `docs/求职_外部基线.md` |
| "为什么候选用 6 个？" | top-k=1 劣化 14.84%（只省 10% CPU），12 无收益且慢 51% → 6 在拐点 |
| "换个城市结论还成立吗？" | 天河重跑：换电/多机稳，跨段归零；并说明"哪个是机制、哪个是几何" |
| "1.5%–3.4% 到底是多少？" | 报区间 + 三个前提（≥2 块电池、换电 ≤5 min、无人机可落地等待），不硬给单点 |

### 3.4 讲的时候要控制的两件事

- **负结果别超过三分之一**：六条"让算法变聪明"的路全负，讲两条即可，用来证明判断力。
- **别说"改进了论文算法"**：改的是模型假设，算法框架是沿用的，说错会被追问到崩。

## 6. 投递建议

**优先投**：京东物流、美团配送、菜鸟、顺丰、华为供应链、字节供应链/决策优化——
这类团队的实习面试就是"讲一个你建模的项目 + 追问细节"，这个项目能撑住 40 分钟。

**可投但要准备好边界**：岗位描述里出现"OR-Tools / 运筹求解器开发 / 服务化"的，重点讲清外部基线的松弛口径与当前 CLI 是本地批处理工具、不是在线服务。

**一句话定位（简历首行可用）**：

> 能独立完成"建模 → 精确解定标 → 大规模启发式 → 统计验证 → 真实路网复核"闭环的运筹项目；
> 主要贡献是定位一处建模缺陷并给出其收益边界（1.5%–3.4%），而非刷单点指标。

**不要写**：不要写"复现某论文"（材料已全部改掉）；不要写"提出了新算法"（没有）；
不要把 51.4% 说成"精度"；不要只报一个百分比而不给样本量。
