## 1. 三十秒版（电梯陈述）

> 我独立复现了一篇 TR-E 上的卡车-无人机联合配送论文：79 条约束的混合整数规划 + 自适应大邻域搜索，
> 16 个算例、每个 10 个种子，节省率做到 51.4%，和论文的 52% 对得上。
> 复现完之后我发现论文里有一个变量承担了两种语义，导致同一节点不能既降落又起飞；
> 我把这个假设放开，用 Gurobi 在 4 个算例上把论文的"已证明最优"全部打破了。
> 后面半程主要在回答一个问题：这个 2% 到底在什么条件下成立。

## 2. 简历条目（按岗位选一个版本）

### 版本 A · 运筹优化 / 算法研究岗

**卡车-无人机联合配送路径优化（独立项目：复现 + 模型改进）**　2026.10–2026.11

- 复现 TR-E 论文的多卡多机双向配送模型（79 条约束，含时间同步、双向载荷、时空禁飞区），
  用 ALNS 在 16 算例 × 10 种子上做到 **节省率 51.4%**（论文 ≈52%），100 客户 CPU **124–187 s**（论文 159–254 s）
- 定位一处建模缺陷（单个 0-1 变量同时表示"降落/起飞"），用 Gurobi 在 **4/4** 个 10 客户算例上
  打破论文最优值（−0.17% ~ −4.33%），新模型**全部证到 gap 0%**
- 设计 5 组口径实验（悬停能耗 / 换电耗时 / 电池库存 / 算例形态 / 空间分布），
  把结论从单点 −2.26% 收敛为**区间 1.5%–3.4%** 并给出失效边界（每车 <2 块电池时失效）
- **12 组**学习型算子选择实验（预筛/UCB/DQN/LLM 造算子/规则干预）全部为负，
  识别出"收益来自算子配比而非决策智能"

### 版本 B · 算法工程 / 后端 / 数据工程岗

**卡车-无人机联合配送求解器（Python，独立开发）**　2026.10–2026.11

- 从零实现求解器 **5.8k 行 / 26 模块** + 实验层 **5.5k 行 / 35 脚本**，**255 项测试**，GitHub Actions CI 全绿
- 性能优化 **4.6×**（几何缓存 / 路线评估记忆化 / 违约早退 / 多进程落盘续跑），
  单候选评估 ~30 µs，160 次求解 20 min 完成且可断点续跑
- 建立三重正确性保障：默认口径**逐位回归**、MILP 与评估器**双实现互查**、同种子**配对统计**（避免极值偏差）
- 一键复现：`reproduce --quick` 4 min 冒烟 / 全量 1.6 h；`project_check` 一条命令查产物与回归

> 一行版（简历空间紧张时）：
> 独立复现 TR-E 卡车-无人机配送论文（MILP + ALNS，节省率 51.4%），用 Gurobi 证伪其一处建模假设
> （4/4 算例最优值被打破），并用 5 组口径实验把结论收敛为 1.5%–3.4% 的区间。

## 3. 面试三分钟讲稿（口语版，可背结构不要背字）

**（20 秒）背景**
"这篇论文做的是卡车带无人机送货：卡车在跑，无人机从卡车顶上起飞，送完在下一个停靠点落回来。
它比普通 VRP 难在三个地方——时间要同步、能耗跟载荷耦合、还有时空禁飞区。"

**（70 秒）我做了什么**
"我先把它复现了：79 条约束的混合整数规划，加一个自适应大邻域搜索。16 个算例、每个 10 个种子，
节省率 51.4%，论文是 52%，10 客户用 Gurobi 全部证到最优。
复现完我去看模型细节，发现它用一个 0-1 变量同时表示'无人机在 i 降落'和'从 i 起飞'。
这在物理上没有理由——换个电池再起飞是常规操作。但用了同一个变量，同一个节点就只能二选一。
我把这个变量拆成到达和出发两套，加回原来的限制时结果和论文逐位相同，
放开限制后 4 个算例的最优值全部下降，而且全部证到 gap 0——
也就是说论文那个'已证明最优'不是最优。"

**（40 秒）最难的地方**
"最难的不是把它解出来，是证明这个下降不是调参调出来的。
我做了三层：统计上同种子配对、16 个算例里 140 好比 20 差；
最优性上用 Gurobi 直接证；
最后把解转回我自己的评估器复算成本和可行性，两套实现必须对上。"

**（30 秒）结果与反思**
"但后面我发现这个百分比不稳。把悬停能耗算进去、把换电本身的两分钟算进去、
把每车电池限制成 2 块，它就从 3.4% 掉到 1.5% 左右。
所以我最后的结论不是'降 2.3%'，而是'降 1.5% 到 3.4%，前提是每车至少 2 块电池'。"

## 4. 高频追问与答法

| 追问 | 答法（要点） |
|---|---|
| **你的数和论文对不上怎么办？** | 明确只对趋势不对绝对值：论文没公开算例改造规则（取件/时间窗/禁飞区/车队规模都是我自定的）。差距分三类写进文档：结构性（成本系数没给）、自造参数、未公开规则。唯一差一个量级的是 Without-detour（0.5% vs 8.2%），我用算术上界证明了是成本结构所致。 |
| **2.26% 会不会是调参调出来的？** | 三个层面回应：① 同种子配对，不是"各种子取最优"；② Gurobi 独立证最优，4/4 算例 gap 0；③ 解只违反 `lr_once` 一条约束——差距精确地来自那一个变量，不是别的地方。 |
| **为什么不用强化学习 / LLM 做算子选择？** | 我试了 12 组，全是负结果：UCB +3.97%、DQN +3.78%、LLM 造算子 7 个里 6 个输给随机。机制是这个 ALNS 的收益来自算子配比，任何"更聪明的选择"都在破坏配比。这条我写成了结论，不是藏起来。 |
| **算例是你自己造的，凭什么叫结论？** | 补了原生形态：把取件、禁飞区、时间窗三条自造约束全拿掉，回到原论文的形态，换电仍然降 4.29%，比默认还大。另外做了四组生成参数扰动、客户聚簇，都稳。 |
| **真实业务里这 2% 意味着什么？** | 报告口径是运营成本，不是车价。我另外算了资本侧：多买一辆车（含司机）反而 +0.67%，所以瓶颈不在车和机，在停靠点密度和地面作业效率。 |
| **给你 200 个客户怎么办？** | 现在上限 100。ALNS 的复杂度主要吃在评估次数上，200 客户单次会到分钟级，可以做候选预筛——但我实测过预筛，墙钟反而慢 2.1 倍（评估器已经很便宜），所以正确方向是并行 + 更好的初始解，不是预筛。 |
| **你怎么保证 MILP 写对了？** | 三道闸门：加回限制必须与原模型逐位相同（等价性）；放开必须严格更优且 gap 0（有效性）；解转回评估器复算，成本与目标值一致。 |
| **最大的技术难点？** | 时间同步的表示。无人机起飞时刻由卡车到达决定，落地时刻由飞行和客户服务决定，卡车在回收点要等——两边互为约束。我最后用"到达/出发拆变量"解决，顺手就发现了论文那个缺陷。 |
| **代码质量怎么保证？** | 255 项测试 + 逐位回归脚本（任何默认路径改动立刻失败）+ CI + 一条命令的项目自检。性能优化 4.6× 的过程中结果一位没变，就是靠逐位回归守住的。 |
| **如果重做一遍？** | 我会先做"结论的边界"再做"结论"。这次是先跑出 2.26% 再回头补悬停、电池、耗时，返工了不少；其实一开始就该把口径列出来。 |
| **这是你一个人做的？** | 是。12 组负结果是证据——没人会把失败的实验一条条写进文档，除非真跑过。 |

**不要说的话**（会掉分）：

- 不要说"我把论文的算法改进了 2%"——改的是**模型假设**，算法骨架一行没动。
- 不要说"完全复现了论文"——绝对值不可比，只有趋势对齐。
- 不要把 51.4% vs 52% 说成"精度 99%"——那是节省率的均值，不是对齐精度。

## 6. 五分钟现场演示（如果让上手）

```bash
python -m scripts.project_check          # 10 s：产物齐、默认口径未变
python -m scripts.paper_figs --only B    # 20 s：重画"四把刀"图
python -m scripts.bench --exp demo --sets 5 --seeds 1 --iters 300 --hotswap
                                         # 3 s：跑一个换电臂，看 cost/saving
```

`docs/milestones/M9.16`（最优性证据表）。三步分别回答"结论是什么 / 能不能跑 / 凭什么信"。
