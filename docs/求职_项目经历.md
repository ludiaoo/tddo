## 1. 三十秒版（电梯陈述）

> 我做了个卡车-无人机联合配送的优化器：一张城市配送网（客户、时间窗、时空禁飞区）进来，
> 输出卡车路线、无人机从哪起飞在哪落回、几点起飞、带几块电池。模型是 79 条约束的混合整数规划，
> 求解用我自己写的自适应大邻域搜索，100 个客户 2–3 分钟出解，比纯卡车方案省 15.9%。
>
> 做完之后我盯住一个建模细节：把"降落"和"起飞"写进同一个 0-1 变量，同一节点就只能二选一——
> 可现实里换块电池再起飞是常规操作。拆开之后，4 个小算例的**已证最优值全部被打破**。
> 后半程我只做一件事：这个 2% 到底在什么条件下成立。

## 2. 简历条目（按岗位选一个版本）

### 版本 A · 运筹优化 / 算法研究岗

**卡车-无人机联合配送优化器（独立设计并实现）**　2026.10–2026.11

- 独立完成问题建模与求解：79 条约束的混合整数规划（时间同步、双向载荷、时空禁飞区、单架次电量），
  自研 ALNS 在 **16 算例 × 10 种子**上做到比初始可行解低 **51.4%**、比纯卡车方案低 **15.9%**，
  100 客户 CPU **124–187 s**
- 发现并修正一处建模缺陷（单个 0-1 变量兼任"降落/起飞"），用 Gurobi 在 **4/4** 个 10 客户算例上
  打破原形式的最优值（−0.17% ~ −4.33%），新模型**全部证到 gap 0%**
- 设计 5 组口径实验（悬停能耗 / 换电耗时 / 电池库存 / 算例形态 / 空间分布），
  把结论从单点 −3.37% 收敛为**区间 1.5%–3.4%** 并给出失效边界（每车 <2 块电池时归零）
- **12 组**学习型算子选择实验（预筛 / UCB / DQN / LLM 造算子 / 规则干预）全部为负，
  识别出"收益来自算子配比而非决策智能"

### 版本 B · 算法工程 / 后端 / 数据工程岗

**卡车-无人机联合配送求解器（Python，独立开发）**　2026.10–2026.11

- 从零实现求解器 **6.4k 行 / 30 模块** + 实验层 **7.5k 行 / 44 脚本**，**341 项测试**，GitHub Actions CI 全绿；`pip install -e .` 后用 `tddo` 命令完成体检、求解与自检
- 性能优化 **4.6×**（几何缓存 / 路线评估记忆化 / 违约早退 / 多进程落盘续跑），
  单候选评估 ~30 µs，160 次求解 20 min 完成且可断点续跑
- 建立三重正确性保障：默认口径**逐位回归**、MILP 与评估器**双实现互查**、同种子**配对统计**（避免极值偏差）
- 一键跑通：`reproduce --quick` 4 min 冒烟 / 全量 1.6 h；`project_check` 一条命令查产物与回归

## 3. 面试三分钟讲稿（口语版，可背结构不要背字）

**（20 秒）背景**

"卡车带无人机送货：卡车在跑，无人机从车顶起飞，送完在下一个停靠点落回来。
它比普通 VRP 难在三处——时间要同步（起飞时刻由卡车到达决定、落地时刻又决定卡车要不要等）、
能耗跟载荷耦合（每送一个客户载荷就变，能耗只能逐段推）、外加时空禁飞区（绕行距离是时间相关的分段函数）。"

**（70 秒）我怎么做的**

"先建模：路由、架次、时间、载荷、能量五组变量，79 条约束分七族。
然后一个设计选择决定了后面所有的工程成本——**把一半约束交给解的表示**：
`Route/Sortie` 三层结构下'只在停靠点起降''流守恒'根本没法被违反，评估器只检查真需要检查的东西，
单个候选 30 µs。有了这个，ALNS 才跑得动 4 破坏 × 4 修复、2000 轮。

跑通之后我盯一个细节：模型里'在 i 降落'和'从 i 起飞'是同一个 0-1 变量，同一个节点只能二选一。
物理上没道理——换块电池再起飞是常规操作。我把它拆成到达、出发两套：
加回原来的限制，最优值逐位相同；放开限制，4 个算例最优值全部下降，而且全部证到 gap 0。
也就是说，这个限制本身在抬高成本。"

**（40 秒）最难的地方**

"最难的不是把它解出来，是证明这个下降不是调参调出来的。
三层：统计上同种子配对，不是'各种子取最优'；最优性用 Gurobi 直接证，4/4 gap 0；
最后把 MILP 的解转回我自己写的评估器复算成本与可行性，两套实现必须对上——
对不上就说明其中一套写错了，这是最便宜的自查。"

**（30 秒）结果与反思**

"但后面我发现这个百分比不稳。把悬停能耗算进去、把换电本身的两分钟算进去、
把每车电池限制成 2 块，它就从 3.4% 掉到 1.5% 左右；如果只带 1 块电池，直接归零——
因为上限只有一个架次，落地之后没有第二次起飞，机制上就无从换电。
所以我最后报的不是一个数，而是'降 1.5% 到 3.4%，前提是每车至少 2 块备用电池'。"

## 4. 高频追问与答法

| 追问 | 答法（要点） |
|---|---|
| **这个模型是你原创的吗？** | 问题形式属于该领域的主流建模（truck-drone tandem），我在 README 里引了出处；求解器、评估器、变量重构、全部实验和结论都是我自己做的。模型形式本身不是贡献，**"这个形式哪里写错了、错多少、在什么条件下错"才是**。 |
| **3.37% 会不会是调参调出来的？** | 三层回应：① 同种子配对（30 个配对），不是"各种子取最优"；② Gurobi 独立证最优，4/4 算例 gap 0；③ 两个解之间只差一条约束——`lr_once`，差距精确地来自那一个变量，不是别的地方。 |
| **为什么不用强化学习 / LLM 做算子选择？** | 我试了 12 组，全是负结果：UCB +3.97%、DQN +3.78%、LLM 造的 7 个算子里 6 个输给随机。机制是这个 ALNS 的收益来自算子**配比**，任何"更聪明的选择"都在破坏配比。这条我写成结论，没藏起来。 |
| **算例是你自己造的，凭什么叫结论？** | ① 换电收益在"纯派送 + 无禁飞区 + 宽时间窗"的形态下更大（−4.29%），说明它不是靠我加的约束撑出来的；② 四组生成参数扰动、客户聚簇（最近邻距离 −50%）都稳；③ 算例生成规则全写在 `configs/`，种子固定，任何人可复算。 |
| **真实业务里这 2% 意味着什么？** | 口径是运营成本，不是车价。我另算了资本侧：多买一辆车（含司机）反而 +0.67%——瓶颈不在车和机，在停靠点密度和地面作业效率。所以这个模型的用法是"给定车队，重排任务"，不是"多买装备"。 |
| **能换算成每单多少钱吗？** | 我把天河 set104 映射成片区一天 100 单冷链补货（均单 6.7 kg、7 辆车）：含无人机 ¥22.85/单、纯卡车 ¥25.60/单，省 ¥2.74/单（10.7%）；司机工时占 81%。成本系数和排放因子都是显式假设，只讲量级，不当报价。详见 `docs/求职_业务场景.md`。 |
| **和已有文献比，新在哪？** | 我不抢首创：多机、禁飞区、双向取派与 ALNS 在 Zeng et al. (2026) 已有。我的差别是三点：把车载备用电池数量、换电耗时与载荷相关能耗写成耦合成本并量化；对参照模型的起降变量与免费悬停两个假设做证伪式检验，报告跨段收益在计费悬停后不显著；以及用逐位回归、同配对统计、OR-Tools 松弛基线和 CLI/容器把口径锁死。详见 `docs/求职_文献定位.md`。 |
| **和 OR-Tools 比呢？** | 已在同批算例上跑 OR-Tools 纯卡车 VRPTW：目标口径与我的评估器 8/8 差值为 0；10/25/50 客户差异 ≤0.01%，天河 100 客户我的 ALNS 纯卡车便宜 4.5% 且墙钟更短。但那是松弛子问题、限时搜索，不能说"全面超过 OR-Tools"。详见 `docs/求职_外部基线.md`。 |
| **给你 200/500 个客户怎么办？** | 我做了固定 50 轮的合成聚簇压测：200 客户 36 s、500 客户 259 s（100→500 约 27×），6/6 都给出可行解；曲线在 `figF_scale_time.png`，口径在 `results/scale_bench.md`。这**只是工程指标**，不拿合成算例报成本收益。候选预筛我实测反而慢 2.1×——评估器已只有 30 µs，筛的开销比省下的多。 |
| **你怎么保证 MILP 写对了？** | 三道闸门：加回限制必须与原形式逐位相同（等价性）；放开必须严格更优且 gap 0（有效性）；解转回评估器复算，成本与目标值一致（双实现）。 |
| **最大的技术难点？** | 时间同步的表示。起飞时刻由卡车到达决定，落地时刻由飞行与客户服务决定，卡车在回收点要等——两边互为约束。我最后用"到达 / 出发拆变量"解决，顺手就发现了那个建模缺陷。 |
| **代码质量怎么保证？** | 341 项测试 + 逐位回归脚本（默认路径一改就失败）+ CI + 一条命令的自检。4.6× 提速过程中结果一位没变，靠的就是逐位回归。 |
| **别人接手怎么跑？** | `pip install -e ".[dev]"` 后直接 `tddo doctor` 体检、`tddo solve --set 104` 求解、`tddo check` 自检；还有 Dockerfile，数据/密钥/许可证都不进镜像，CI 里会验证安装和镜像构建。 |
| **如果重做一遍？** | 我会先做"结论的边界"再做"结论"。这次是先跑出 3.37% 再回头补悬停、电池、耗时，返工不少；一开始就该把这些口径列成清单。 |
| **这是你一个人做的？** | 是。12 组负结果是证据——没人会把失败的实验一条条写进文档，除非真跑过。 |

**不要说的话**（会掉分）：

- 不要说"我把某个算法的精度提升了 2%"——改的是**建模假设**，算法骨架一行没动。
- 不要只报一个数（"降 2.3%"）——正确说法是**区间 1.5%–3.4% 及其前提**，这是我的核心贡献之一。
- 不要把 51.4% 说成"比论文好"——那是相对**自己的初始可行解**的降幅，不同算例不可横比。
